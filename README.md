# Лидерборд научного музея

Рейтинг игроков для интерактивного музея: дети выбирают аватар (эмодзи и три буквы), проходят игры на стендах, очки сами попадают на большой экран. Экран умеет показывать группу как молекулы в жидкости и в газе.

Живая версия: https://plairpro.github.io/museum-leaderboard/

## Экраны

| Страница | Для кого | Что делает |
|---|---|---|
| `index.html` | большой экран в зале | рейтинг по убыванию очков; режимы «Жидкость» и «Газ»; кнопка «Смотритель» |
| `register.html` | сопровождающий группы | 30 аватаров, нажатие занимает, повторное (дважды) освобождает |
| `stand.html` | проверка | тестовый стенд: выбрать зверя, набрать очки, отправить |

**Смотритель.** Кнопка в правом верхнем углу, PIN-код по умолчанию `1984`, вводится на экранной клавиатуре. Внутри: сброс лидерборда и аватаров (двойное нажатие), переход к выбору аватаров, тестовый стенд, полноэкранный режим. Сменить PIN: в консоли браузера `Museum.hashPin('новый')`, результат вставить в `pinHash` в `sdk/museum-sdk.js`.

**Подсчёт очков.** По умолчанию (`scoring: 'best'`) в каждой игре засчитывается лучший результат ребёнка, по играм результаты складываются: переигрывание одной игры не накручивает очки. Вариант `'sum'` складывает все прохождения. Равные очки делят место, выше стоит тот, кто набрал их раньше.

**Молекулы.** Баллы превращаются в валентность: верхняя четверть игроков держит 4 связи (как углерод), следующие 3 (азот), 2 (кислород), остальные 1 (водород). Размер круга — доля от лучшего результата. В жидкости связи пунктирные (водородные), живут 1–5 секунд и перецепляются; в газе молекулы летят и сталкиваются упруго, связь вспыхивает в момент удара и рвётся. Тяжёлые (с большими очками) летят медленнее: скорость ~ 1/√m.

## Подключение игры

```html
<script src="https://plairpro.github.io/museum-leaderboard/sdk/museum-sdk.js"></script>

<!-- на стартовом экране, внизу -->
<div id="avatar-picker"></div>

<script>
  let avatar = null;
  const picker = Museum.mountPicker(document.getElementById('avatar-picker'), {
    onChange(code) { avatar = code; startButton.disabled = !code; }
  });

  // в конце игры
  Museum.submit({ avatar, points: 120, game: 'magnets' })
    .then(() => { picker.value = null; /* следующий игрок */ });
</script>
```

- Пикер показывает только аватаров, занятых группой, и сам обновляется.
- `game` — короткий идентификатор игры, одинаковый на всех стендах с этой игрой.
- `Museum.subscribe(state => …)` и `Museum.standings()` — если игре нужно показать рейтинг у себя.

## Связь между стендами

Без настройки всё работает в **локальном режиме**: очки видны только в одном браузере одного компьютера (удобно для проверки, все вкладки синхронизируются).

Для зала, где стенды — разные компьютеры, нужен общий сервер. Используется Firebase Realtime Database через REST, без SDK и сборки:

1. Создать проект в https://console.firebase.google.com, включить Realtime Database.
2. Правила базы (открытый доступ только к узлу музея):
   ```json
   { "rules": { "museum": { ".read": true, ".write": true } } }
   ```
3. Вписать адрес базы в `firebaseUrl` в `sdk/museum-sdk.js` — или, не меняя код, открыть на каждом стенде и экране один раз ссылку вида
   `…/index.html?db=https://ИМЯ-default-rtdb.europe-west1.firebasedatabase.app` — адрес запомнится в браузере.
4. Несколько залов: `?room=hall-2`, у каждого зала свой рейтинг.

PIN-код защищает интерфейс смотрителя на экране, а не саму базу: база открыта на запись, как и любые данные музейного табло.
